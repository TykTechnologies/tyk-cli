<h2 id="sec-2">2. General Description</h2>



<h3 id="sec-2-1">2.1 Product Perspective</h3>
<p><strong>tyk-cli</strong> is a requirements engineering tool designed for teams that
need formal verification of their specifications. It occupies a unique position in the requirements
ecosystem:</p>
<ul>
  <li><strong>Compared to IBM DOORS / Jama Connect:</strong> tyk-cli provides git-native
  storage (YAML files under version control) rather than a proprietary database, enabling standard
  code-review workflows and offline access.</li>
  <li><strong>Compared to NASA FRET:</strong> tyk-cli adds persistent storage, traceability
  management, gap analysis, and document generation on top of FRETish compilation, operating as a
  complete requirements lifecycle tool rather than a formalization workbench.</li>
  <li><strong>Compared to Doorstop:</strong> tyk-cli adds formal verification (realizability,
  consistency, vacuity checking via Kind2/JKind) and automated MC/DC test generation via the FLIP
  algorithm.</li>
</ul>

<h3 id="sec-2-2">2.2 Product Functions</h3>
<p>At a high level, tyk-cli provides the following capabilities:</p>
<ul>
  <li><strong>Compile:</strong> Parse FRETish requirements (288 semantic templates) into future-time and
  past-time LTL, and CoCoSpec Lustre contracts.</li>
  <li><strong>Verify:</strong> Check realizability, consistency, and vacuity of formalized requirements
  using Kind2 or JKind model checkers, with assurance levels A through E.</li>
  <li><strong>Analyze:</strong> Perform gap analysis across 7 categories (parent traceability, test
  coverage, implementation links, formalization completeness, review status, output determinism,
  assumption coverage).</li>
  <li><strong>Test:</strong> Generate MC/DC test cases from temporal logic formulas using the FLIP
  algorithm (Formal LTL-based Input Partitioning).</li>
  <li><strong>Generate:</strong> Produce NPR 7150-compliant SRS documents, traceability matrices,
  verification reports, and requirement summaries in HTML and Markdown formats.</li>
  <li><strong>Manage:</strong> Baseline requirements, track changes, compute diffs between baselines,
  and maintain full provenance records.</li>
</ul>

<h3 id="sec-2-4">2.4 Constraints</h3>
<ul>
  <li>Formal verification (realizability, consistency, vacuity) requires Kind2 or JKind to be installed and accessible on the system PATH.</li>
  <li>The FRETish compiler supports the 288 semantic templates defined by NASA FRET; requirements outside this template space must use manual LTL or informal verification strategies.</li>
  <li>Document generation currently supports HTML and Markdown output; PDF generation requires a future chromedp (headless Chromium) integration.</li>
  <li>The tool is distributed as a single Go binary; the Go runtime is statically linked and not required at deployment time.</li>
</ul>

<h3 id="sec-2-5">2.5 Assumptions and Dependencies</h3>
<ul>
  <li>The FRETish semantic engine is based on the 288 NASA templates from the FRET project (Giannakopoulou et al., NASA Ames).</li>
  <li>The ANTLR4-compatible grammar defines the FRETish language syntax; changes to the grammar may affect requirement parsing.</li>
  <li>Kind2 and JKind are external SMT-based model checkers maintained independently; solver compatibility is tested against Kind2 v1.x and JKind v4.x.</li>
  <li>Git is assumed to be available for repository operations (baseline creation, change tracking).</li>
</ul>

<h3 id="sec-2-8">2.8 Interface Requirements</h3>

<h4 id="sec-2-8-1">2.8.1 User Interfaces</h4>
<p>ReqProof provides three user interfaces:</p>
<ul>
  <li><strong>CLI</strong>: 21 commands accessed via <code>proof &lt;command&gt;</code></li>
  <li><strong>Web UI</strong>: SvelteKit application served by <code>proof serve</code></li>
  <li><strong>MCP</strong>: JSON-RPC over stdio for AI agent integration via <code>proof mcp</code></li>
</ul>

<h4 id="sec-2-8-3">2.8.3 Communication Interfaces</h4>
<p>External protocols:</p>
<ul>
  <li><strong>HTTP REST</strong>: JSON over HTTP/1.1 on configurable port</li>
